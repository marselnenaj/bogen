# Canonical brandbooks

Each new brand owns a synchronized book in its existing brand document. The Brandbook tab is the default landing view. Sixteen stable chapters cover strategy, audience, architecture, principles, logos, colour, typography/languages, responsive layout, imagery, icons, voice, motion, data, applications, accessibility and governance. The existing structured palette, assets, fonts, voice and hard/soft rules remain authoritative; this book adds rationale, operating examples and unresolved decisions rather than replacing them.

A chapter has Markdown, its actual source, open questions, review state, author/time and an opaque revision. Agents can write drafts or open questions with `brand_book_update`; `brand_book_get` reads a compact outline or one full chapter. Only a person can confirm a sourced chapter with no remaining questions, or mark a chapter not applicable with a rationale. Confirmed decisions must be reopened by the person before agents can edit them. Changes do not publish a brand version, apply tokens to other files or approve designs automatically.

Human edits use the existing shared document and native undo/redo. The local editor buffer survives synchronization and revision conflicts; save never happens on blur. Independent chapters use separate CRDT entries. A stale same-chapter revision is refused; cross-device simultaneous edits still follow normal CRDT conflict resolution and are not a distributed lock. Legacy documents remain readable without migration. Unsupported formats and damaged chapter entries are not overwritten by updates.

Runs receive a bounded summary of confirmed guidance and a pointer to read the relevant full chapters. Draft text is not inserted as binding instructions. The current user request and structured identity take precedence. All brand content remains untrusted design data. Exported Markdown includes the full editable book, states, sources and questions. PDF remains the visual foundation sheet with a chapter index and an explicit pointer to the full Markdown book.

Readiness reports documentation coverage and missing confirmed foundations. It is not a visual quality score, accessibility certificate, legal clearance or evidence of user approval. A person may leave decisions open; unsupported audiences, research, ownership, licences and product claims must never be fabricated to fill a chapter. Concrete applications still need screenshots, conformance checks, keyboard/narrow/large-text testing and review.

The Brand system file button reopens an existing linked visual guideline with a Brand system page, or creates one canonical destination when none exists. Concurrent clicks are coalesced. It does not generate another file for each revision. Agent template tools still allow explicit new deliverables when requested; use an existing `file_id` for additions.

Implementation checks cover legacy compatibility, revision conflicts, human review, malformed/oversized data, sync, undo, version round trips, agent prompt isolation, exports and canonical file reuse. Browser interaction checks use an isolated fixture, including editing, review, undo/redo, synchronization conflicts, narrow layouts and reload persistence.
