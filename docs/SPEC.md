# Bogen: product spec

Bogen is an open source design canvas where every design is real HTML and CSS. People draw on it, and their own coding agents (Claude Code, Codex, anything that speaks MCP) draw on it too, using their own plans. No subscription, no account, no usage cap. Local first, optional self-hosted team server, first-class on Omarchy.

## Clean-room rule

Everything here is written from scratch. Inputs allowed: public marketing pages, public docs and changelogs of design tools, web standards, permissively licensed npm packages. Never read, copy or derive from: the Paper Desktop app or its bundles, or any reverse engineered clone of a design tool. Bogen uses its own MCP tool names, schemas and messages.

## Architecture

```
packages/core    Yjs document model, operations, HTML import, render rules, HTML/JSX/Tailwind export
packages/server  `bogen` CLI: HTTP + WebSocket sync, file storage, MCP (stdio + HTTP), headless
                 Chromium rendering, agent runner
apps/editor      React canvas, served by the server
integrations/omarchy  bar widget, theme hook, launcher, Hyprland rules, installer
```

- The document is a Y.Doc. Editors, other people and agents are all peers of the same CRDT, so multiplayer is not a special case. The server holds a replica and persists it.
- MCP tools apply operations to the server replica with origin `agent:<name>`. They work with no editor open. Screenshots and layout come from headless Chromium rendering `core`'s render rules, so canvas, screenshot and export agree.
- Undo: `Y.UndoManager` per actor. A person undoes their own edits in the editor; agent edits can be undone per agent through the server, by the person or by the agent with `agent_undo`.
- Transaction origins say who made a change: `agent:<name>`, `peer:<id>`, `person:<name>` for a comment sent through the API, the socket for an editor. `FileEvents` reads them to log what happens per file. It only observes: nothing in a document can start a process.
- Data lives under `$BOGEN_HOME` (default `$XDG_DATA_HOME/bogen`, else `~/.local/share/bogen`): `files/<id>.ydoc`, `assets/<sha256>.<ext>`, `history/<id>/`, `index.json`, `config.json`, `phone.json`.
- The server listens on 127.0.0.1:29990 by default and rejects foreign `Origin`/`Host` headers. `--host` with a required `--token` enables the team server.

## Design of the editor

Dense, calm, keyboard first. No eyebrow labels, cards, glow or all caps. UI font Source Sans 3, code in the mono only inside the code panel. Chrome colours come from CSS variables so that the Omarchy theme can drive them (`--ui-bg`, `--ui-bg-2`, `--ui-bg-3`, `--ui-fg`, `--ui-fg-2`, `--ui-border`, `--ui-accent`, `--ui-accent-fg`, `--ui-danger`). The canvas surface is never themed by a design's content.

### Brand

A brand is a document of its own kind: a Y.Doc with `meta.kind = 'brand'`, so that sync, undo, multiplayer, history and `.bogen` files apply unchanged. Its content is in the shared maps `brandFields`, `brandItems` and `brandVersions`, its pages hold the example artboards, and a file points at one through `meta.brandLink`. Old files have none of this and work as before. ## History

One mechanism, not a bolt-on: the timeline says what happened, commits say where things stood, and both travel with the file.

- Timeline: `$BOGEN_HOME/history/<id>/changes-<device>.jsonl`, one append-only log per device, with who, when, which tool or action, which layers, and for each field the value before and after. A server keeps a plain copy of each loaded file to compute this, so a transaction costs what it touched. A person's quick edits to the same layers within 1.5 s are one entry; an agent's tool calls stay apart. Local-only `received.jsonl` holds what arrived from a device that does not send its own log, and is hidden once that device does.
- Retention of changes, per file and device: the last 30 days up to 32 MB in full, older details dropped, oldest first, with who, when, which tool and which layers kept, to 50,000 entries. A thinned change cannot be reverted, and says so.
- Commits: `<id>.json.gz` and `commits.json`. Named commits by people and agents are kept for good. Commits from agent runs and restore points are kept until the file passes 256 MB of commits, oldest first. Automatic commits every few minutes thin out: the latest 24, one per hour for a day, one per day for a month.
- Revert: turns a field back only if it still holds what the change left. Otherwise it is listed with the reason, and the rest still goes back. A layer that gained children since stays; a layer whose parent is gone cannot come back. A revert is a change, and can be reverted. In the editor it is also one Ctrl+Z.
- Restore commits what it replaces first, then applies the commit as one change. Layers, pages, tokens, keyframes and other document data go back; comments stay as they are, though a single comment change can be reverted. Fonts are only ever added.
- Sync: logs and commits go to paired devices over the existing peer link, with device names. Automatic commits stay on the device that made them. Not included in `.bogen` files or design folders, which hold the design as it is.

Rules, additive on the layer's map: `rules`, a flat Y.Map of `<block>#<property>` to a value, where a block key reads like CSS (`::before`, `:hover`, `parent[open]::after`, `@container card (max-width: 560px) ::after`, `@media (max-width: 760px) :hover`). On instances, overrides `rule.<property>.<block>`. `packages/core/src/layer-rules.ts` parses blocks, checks values and writes the one style sheet (`layerRulesCss`), for the class `bgn-<id>` that `renderSpec` adds; `artboard` mode makes the top-level layer a container named `bogen-artboard` for media width queries. Older builds ignore the field.

Component data, all additive on the layer's map: `instanceOf`, `props` (Y.Map), `overrides` (Y.Map of `<path>#<field>`), `component` (Y.Map with `description`, `set`, `variant`, `props`), `slotName`, `slot`, `mode`, `textStyle`. Tokens gain `mode:<name>` keys next to `value`, pages a `mode`, and the document the top-level maps `modes`, `textStyles` and `snapshotSources`. Ids inside an instance are `<instance>/<layer in main>`, and are never stored as layers. `packages/core/src/components.ts` is the one resolver, used by `BogenDoc` and the editor's snapshot. A code component is an `embed` with `code` (`{project, file, name, import?}`) and `codeProps` (Y.Map); projects live per device in `code-projects.json`, and a file names its project in `meta.codeProject`. Libraries: the document maps `libraryPublished` and `libraries`, `meta.library`, and copies of library components under the parent `lib:<library id>` with a `library` field on their root (`packages/core/src/library.ts`).

Editor awareness state: `{ user: { name, color }, cursor: {x, y, pageId} | null, selection: string[], pageId, chat?: string }`. Agents appear through the same awareness with `user.agent = true`, and may add `focus: { id, pageId?, nodeIds, select, view, note?, at }`, which an open editor follows once per id when the person is not busy. A person on another device appears with `user.device`, and does not count as someone here.

Peer protocol, additive: every request and socket says `X-Bogen-Version` and `X-Bogen-Features`, and a manifest has `version` and `features`. The socket message `{t:'presence', id, people}` only goes to a device whose features list `presence`. A message of an unknown kind is ignored.

A text layer's words are a `Y.Text` under `rich` with formatting attributes (`SPAN_STYLE_KEYS`, `href`); `text`, `spans` and `richMark` mirror it for older builds, written in the same transaction. Plain copies (commits, folders, change logs) hold only `text` and `spans`. Code: `packages/core/src/text-model.ts`.

A proposal is a layer with a `proposal` field on its map: `{ of, by, note?, group?, placed?, at }`. It is not part of `BogenNode`, and a copy of it is not a proposal.

Asset URLs in documents are `bogen-asset:<name>`. An image layer with no `src` is a placeholder.
